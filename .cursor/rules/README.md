# Cursor Rules

Persistent runtime constraints for Cursor IDE sessions.

## Purpose

Rules adapt framework law into always-on guidance: artifacts over chat, continuity read/write habits, workflow gates, voice constraints, and review quality expectations.

## Sprint status

Sprint 1 does **not** ship rule packs yet. Later sprints will add layered rule files under this directory (for example: framework core, continuity, style/voice, workflow gates, review quality).

## Design expectations

When rules are added, they should:

- Cite specification IDs instead of re-authoring the entire vision
- Enforce gates without blocking legitimate human overrides that update artifacts
- Remain model-agnostic where possible

## Authority

Rules are runtime adapters. They sit below foundational specs and approved book contracts in the authority stack. See [`../../docs/specifications/001_ARCHITECTURE.md`](../../docs/specifications/001_ARCHITECTURE.md) (Cursor Integration; Document Hierarchy).
